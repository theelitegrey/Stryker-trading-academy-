Close the stored-XSS holes: sanitise user HTML, escape every user field

A security audit found that user-authored markup was rendered raw in three
places and user-chosen names, emails and image URLs were interpolated into
markup unescaped in several more. The worst path was not against students but
against staff: a post rendered raw in the moderation queue executes in an
admin's session, and creating an admins/{uid} document is one call away from
there.

There was no HTML sanitiser on the site at all, and roughly forty-five
per-file escape helpers of varying quality — several stopped at < and >, which
is safe in a text node and useless inside an attribute.

What changed:

- assets/sanitize.js — one shared set of helpers: stkEsc (all five HTML
  characters), stkUrl (http/https or a relative path, nothing else), stkImgUrl
  (https: or data:image/ only) and stkHtml (DOMPurify with a tight allow-list).
  stkHtml FAILS CLOSED: with no DOMPurify loaded it escapes rather than
  renders. DOMPurify 3.2.7 is vendored rather than pulled from a CDN, so it is
  covered by the same cache-busting and adds no third-party origin.
- Trading Floor posts are sanitised on save AND on render, in the feed, on
  public profiles and in the moderation queue. Sanitising before linkifyTags
  matters: that helper parses the markup into a detached div, which is enough
  to start loading an image and fire its onerror.
- Avatar URLs (customPhotoURL / photoURL, both self-written) now go through
  stkImgUrl and fall back to the generated avatar instead of rendering a value
  that could break out of the src attribute. Initials are restricted to
  letters and digits, because they are nested inside a JS string inside an
  HTML attribute where escaping alone would not hold.
- Every user-controlled field in the five admin list views is escaped:
  orders, commerce, referrals, students and the overview.
- Every escaper that stopped at < and > now handles quotes too.
- Notification links and the post-sign-in return path are scheme-checked, so
  a javascript: link written by another user's client and a protocol-relative
  //host redirect are both rejected.
- The push service worker only navigates to paths on this origin.
- stream-overlay.html wrote its ?session= parameter straight into innerHTML;
  it uses textContent now, and the ticker is escaped.

Verified headless: thirteen payload shapes (img onerror, svg onload, iframe
javascript:, form action, xlink:href, entity-encoded handlers, style import)
all render inert, legitimate rich text and hashtag spans survive intact,
attribute breakout via avatar URL and display name is blocked, and no page
in a twenty-four page sweep gained a JS error.
